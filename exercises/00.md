# Exercise 00 - Complete instrumentation

The service records Tokio runtime activity, but Axum starts its connection
tasks with ordinary `tokio::spawn`. Dial9 can see those tasks being polled, but
cannot connect them to their spawn and wake history.

```bash
# run the app 
cargo workshop-app
# run the bencher
cargo hotlap --exercise 00
```

Stop the app, open its trace, and inspect **Uninstrumented polls**. Why do the
connection tasks point into `axum/src/serve/mod.rs`, and what information is
missing?

<details>
<summary>Hints</summary>

1. Runtime hooks can observe a poll without knowing where the task came from.
2. These tasks are created inside Axum and Hyper, not in application code.
3. Dial9 provides an Axum server wrapper that instruments those internal
   spawns.

</details>

```bash
git apply solutions/00.patch
cargo hotlap --exercise 00
```

After the patch, Axum and Hyper tasks carry spawn, wake, and scheduling
information. A few unrelated uninstrumented tasks may remain.
