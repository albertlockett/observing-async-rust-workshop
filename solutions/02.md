# Solution 02

The baseline trace shows a tail-latency problem, but runtime telemetry cannot
name the business operation inside a generic Axum task.

`02-instrumentation.patch` adds a low-cardinality `http.request` span and spans
around catalog, pricing, inventory, suggestions, and recommendation operations.
It does not change the bug:

```bash
git apply solutions/02-instrumentation.patch
```

Almost every `http.request` then contains a mostly idle `suggestions.fetch`
span, even though only 5% of the workload explicitly requests suggestions. The
route treats a missing `suggestions` parameter as enabled.

`02-fix.patch` changes the default from `true` to `false`:

```bash
git apply solutions/02-fix.patch
```

Ordinary searches stop costing extra backend latency. Explicit typeahead requests
remain slow, so p50 and p90 improve even though p99 may not.
