# Solution 04

The route spawns each recommendation fetch and applies the 25 ms timeout to its
`JoinHandle`. The timeout therefore cancels only the future waiting for the
spawned task. Dropping that handle detaches the task rather than aborting it, so
the fetch keeps running after the request returns and its result is discarded.
Requests remain fast while unused work accumulates behind them.

The patch applies the timeout directly to `Recommendations::fetch`. A timeout
now drops the fetch future itself, cancelling its local work. In production,
dropping an HTTP client future releases our local resources, although the
remote server may still finish work it already received.

```bash
git apply solutions/04.patch
cargo hotlap --exercise 04
```

Request latency should remain similar, but recommendation spans should end at
the budget and **Active tasks** should no longer climb.
