# Solution 01

The catalog refresh calls a legacy synchronous storage operation from an async
task. Its roughly 500 ms poll occupies a Tokio worker the entire time.

This patch moves the complete synchronous read and parse into `spawn_blocking`,
then updates shared state on the async task. The operation still takes 500 ms
wall time, but it no longer blocks a runtime worker.

```bash
git apply solutions/01.patch
cargo hotlap --exercise 01
```

The refresh should still take roughly 500 ms, but that time should move off the
Tokio worker and disappear from **Longest polls**.
